# Current strategies → StrategyDefinition: classification and incremental migration

Evidence base: a read-only AST inventory of 27 strategy/research modules and 315
functions (`data/strategy_code_inventory.csv`, `data/inventory_summary.json`,
regenerated by `tools/inventory_strategy_code.py`) plus targeted reading.  Classification
below is reviewed judgement, informed by — not computed from — those signals.

## 1. Constraints from the repository itself

| Constraint | Evidence | Consequence |
|---|---|---|
| **Frozen identity is source-hash based** | Context: `decision_code_hash()` hashes the *source of five functions* and `assert_frozen()` refuses to start on mismatch; Liquidity: `source_sha256_at_start` over `liquidity_displacement.py` bytes, **"strategy source hash changed; refusing to run"** | legacy strategy files **cannot be edited** (no annotations, no refactors, no re-indenting); adapters must sit *outside* them |
| Identity is code + config, not definition | freeze manifests record `code_hash`, `configuration_hash` | declarative strategies need a new identity kind; legacy keep theirs verbatim (`07_…` §2) |
| Detection is intertwined with persistence in Context | `_process_bar` mutates a state dict and calls `append_event` | not wrappable as a pure function without modification |
| Detection is pure and separable in Liquidity | `LiquidityDisplacementStrategy.find_candidate/evaluate(m15, m5, quote, contract, timestamp, i)` | wrappable |
| Causality by convention | only 27 of 315 functions take `as_of`; Liquidity relies on the caller passing arrays that end "now" | the runtime's `MarketView` makes it structural |

Observations that shape the design:

1. **Two strategies were found to be sequences with bounded windows** (Liquidity, sniper);
   the third (Context) is a lifecycle.  `SEQUENCE` covers the first two exactly; the
   Context lifecycle (re-entry, target-completed returns) motivates the reserved
   `STATE_MACHINE` kind and is the reason not to migrate it first.
2. **The dominant duplication is between "strategy" and "telemetry/report" code**
   (Liquidity `decision_telemetry`; the rejection-wick logic re-implemented inline in
   Context `_m5_mechanisms`).  A single evaluation path removes it.
3. **Parameterisation is inconsistent**: dataclass (Liquidity), prose dict + inline
   literals (Context), mapping argument (sniper).  ParameterSets unify it; the *four*
   Liquidity instances are already ParameterSets.
4. **Hard-coded environment leaks into strategy code**: Wine binary/prefix paths and a
   subprocess call in the Liquidity runner; MT5-shaped `quote`/`contract` dicts
   (`tick_size`, `stops_level`, `point`) are consumed by the detector.  The MT5-shaped
   dicts belong in the legacy **adapter**, never in Studio or the declarative runtime.

## 3. Recommendation: two runtimes, one canonical result — **appropriate here**

`LegacyStrategyRuntime` and `DeclarativeStrategyRuntime` both implement
`StrategyRuntime` (`06_…` §4) and emit the same `Evaluation`.  This is appropriate
because the repository forces it: frozen hashes prevent in-place refactoring, and one of
the two live strategies is cleanly wrappable while the other is not.

| Strategy | Adapter approach | Fidelity | Risk |
|---|---|---|---|
| **Liquidity Displacement** | `LegacyLiquidityRuntime` imports the **unmodified** `LiquidityDisplacementStrategy` and calls `evaluate(m15, m5, quote, contract, ts, i)` for the last N anchor bars each cycle — exactly as `detect()` does (`range(max(40, len(m5)-18), len(m5)-1)`) — over arrays truncated at `as_of` by `MarketView`; maps the returned candidate and the existing `decision_telemetry` rows into `Evaluation`/stages | **L2** | low; the adapter carries the MT5-shaped dict conversion, isolated |
| **Context** | **read-only event translator**: tail the existing events/state and emit `Evaluation`s (`SETUP_DETECTED`, `SETUP_INVALIDATED_BEFORE_ENTRY`, `NO_RETRACE`, `FILLED`, flags → `FLAG` stages) | **L1** | none to the runner; no per-bar `NO_CANDIDATE` evaluations (accepted) |
| Research sniper families | port to declarative directly (no frozen identity) | **L3** | low; they are the pilot |

Neither adapter changes a legacy file, a hash, an event, or runtime behaviour.

## 4. Incremental path

| Step | What | Gate |
|---|---|---|
| **M0** | Define `Evaluation`/`DecisionTrace` schema, the reason-code registry (seed from the mapping in `05_…` §3), and the `StrategyRuntime` protocol.  No code touches legacy | schema review |
| **M1** | Legacy adapters: Liquidity runtime wrapper (L2) and Context event translator (L1) writing to `strategy.evaluation`; Console can already show traces for **existing** strategies | adapter output equals existing telemetry/events on a recorded corpus |
| **M2** | Primitive registry + parity harness: implement seed primitives (bar geometry, ATR variants, EMA, swings, zones, engulfing/rejection/star, displacement, sweep, micro-break, touch-and-hold) each with golden vectors, truncation test and **parity against each cited legacy implementation**.  Divergences are **registered as separate versions**, not reconciled | every primitive `APPROVED` with parity report |
| **M3** | Declarative **twin** of Liquidity Displacement: express it as the definition + four ParameterSets; run in shadow against the legacy strategy on recorded and live-forward bars; compare candidates/fills/stops/targets and stage outcomes.  **The legacy strategy remains the production identity**; the twin proves the model and yields L3 traces | zero unexplained divergence; every difference in the **divergence register** |
| **M4** | Author new strategies declaratively from the start (pilot: port the liquidity sniper research, then the multi-timeframe HYBRID example) with the Studio flow | first frozen declarative version through PAPER |
| **M5** | Retire duplicated telemetry (`decision_telemetry`) *only when* a legacy strategy is itself retired or superseded — never by editing a frozen file | — |

### Divergence register (seeded from the reading)

Parity must reproduce, or explicitly document, these legacy behaviours:

* `structure.micro_break` window: `m5[max(i-5, i-12):i]` ≡ last **5** bars (the 12 is dead code);
* ATR is computed **at the sweep bar including it** (`atr(m5[i-119:i+1])[-1]`), and the median body over the 12 bars *before* the sweep — both bound to the sweep stage (`f.atr@s.sweep`);
* **spread is the current quote's spread at evaluation time**, applied to every recently re-evaluated anchor (not the spread at the sweep bar) — `market.spread` in the definition;
* `m15` is a data-sufficiency requirement only (`data_requirements.structure.min_bars = 30`);
* `find_candidate` takes the **first** qualifying displacement (`select: FIRST`);
* session extremes use UTC 08:00–21:00 of the *last bar's* date, 36-bar look-back, swings with lookback 2;
* the retrace fill requires a **touch and a close on the entry side** (`touch_and_hold`), within `max_retrace_candles` after the displacement bar;
* `entry_time = fill bar open + 300 s` (bar close) — becomes the stage `event_time`.

## 5. What is deliberately **not** attempted

Rewriting the Context strategy declaratively (lifecycle, re-entry, target-completed
returns, two-leg risk) before the `STATE_MACHINE` kind is designed; touching any hash-guarded
file; unifying divergent primitives; migrating research scripts other than as pilots.
